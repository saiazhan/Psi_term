# PsiTerm

Веб-панель управления устройствами и серверами через SSH. Версия интерфейса: **v0.2.0**. Это интерактивный frontend-прототип, не готовая система авторизации или удалённого доступа.

## v0.2.0
- Светлая тема по умолчанию и тёмная альтернативная; выбор сохраняется в браузере.
- Русский, казахский и английский интерфейс; язык сохраняется в браузере.
- Роли Simple / Expert / Admin: Simple видит устройства и избранное; Expert получает обзор статусов онлайн/офлайн; Admin видит обзор, пользователей, управление устройствами и тикеты.
- Избранные устройства со звёздочкой.
- Компактная шапка страницы устройства.
- Демонстрационная полоса прогресса подключения; реальное время отклика появится только после backend-проверки.
- Раздел «Информация» оставлен пустым/зарезервированным.
- Обсуждение устройства с автором и временем сообщения; макет выбора изображения/видео с лимитом 50 МБ.
- Административный макет тикетов с шаблонами: термопринтер, связь, автозапуск и другая проблема.
- Кнопка скачивания для обычных файлов; системные пути /home, /home/psi2, /home/psiuser, /etc и /var помечены защищёнными.
- Обновлённая PostgreSQL-схема для предпочтений, избранного, комментариев, вложений, тикетов и защищённых путей.

## Запуск
Откройте `index.html` или запустите локальный HTTP-сервер:
```bash
python -m SimpleHTTPServer 8000
```
Затем откройте `http://localhost:8000`. Любой непустой логин и пароль открывают демо-интерфейс; это не настоящая проверка пароля.

## Ограничения прототипа и следующий этап
- Все демонстрационные устройства, пользователи, комментарии и тикеты хранятся в памяти страницы. Избранное, язык и тема сохраняются в localStorage этого браузера.
- Файлы не передаются и не скачиваются; вложения пока только проверяются по размеру и отображаются как имя файла.
- Прогресс подключения имитируется; реальный SSH RTT/latency не измеряется. Разрыв соединения меняет только демо-статус.
- Уведомления по тикетам не отправляются. Раздел тикетов пока отображается только Admin.
- Проверки защищённых путей в frontend нужны только для макета. Backend обязан повторно проверять нормализованный путь и права на каждую операцию, запрещать обход через symlink/path traversal и вести audit log.
- PostgreSQL не подключён; SQL — проект схемы.
- Не вводите реальные учётные данные и не публикуйте прототип как защищённую панель.

Для backend используйте поддерживаемую ОС и Python 3, безопасные сессии, хеширование паролей, серверный RBAC, HTTPS/CSRF-защиту, ограничения запросов, SFTP с allowlist-политикой, проверку типа и размера файлов, хранение вложений вне webroot и аудит. Python 2.7 и Ubuntu 12.04 сняты с поддержки и не подходят для публичной production-системы.
